# vivo Log 页面数据的交叉验证

对象：`/colour/vivolog/` 页面上的原色、白点、矩阵、曲线。
来源：`vivo Log Technical Specification_v1_0.pdf`（vivo × Bluelmage，2026-08-05，8 页）
与同目录的 `vivoLog_to_ACES_AP0.dctl`。

验证思路：**同一个量用两条独立路径各求一次**——
一条是规格书直接印出来的数，一条是我用原色/公式重建出来的数。

---

## 1. 传递函数：规格书参数 ↔ DCTL

规格书 §1.1（OETF）与 §1.2（EOTF）给出的形式与参数：

```text
E'log = c·log10(a·E_lin + b) + d ,   E_lin > t1
      = e·E_lin + f              ,   否则

a = 5.558556   b = 0.076581   c = 0.265817   d = 0.382516
e = 5.775961   f = 0.092813   t1 = 0.006132   t2 = 0.128231
```

DCTL 里的解码：

```c
if (x > 0.128231) (pow(10, (x - 0.382516) / 0.265817) - 0.076581) / 5.558556;
else              (x - 0.092813) / 5.775961;
```

逐项对照：`a b c d e f` 六个数、断点 `t2 = 0.128231`、
以及线性支的斜率与截距，**全部一字不差**。DCTL 就是规格书 EOTF 的逐字实现。

页面曲线用的是规格书 OETF（编码方向），参数同上。

**锚点**：

| 量 | 规格书 | 页面曲线 |
|---|---|---|
| 18% 灰码值 | "about 0.391" | 0.3911 |
| 码值 1.0 对应相对曝光 | 图 2 约 +7.7 档 | +7.72 档 |
| 黑位（E_lin = 0） | 图 2 约 0.09 | 0.0928 |

**一处规格书自身的小瑕疵**（不影响页面）：
两条分支在断点处不严格相接——OETF 对数支在 t1 给出 0.128399，
而 EOTF 的断点是 0.128231，差 1.7e-4 码值；EOTF 侧同理（0.006103 / 0.006132）。
应是参数各自四舍五入到 6 位小数所致。页面按规格书原文取 t1 / t2，保留这个量级的折角。

## 2. Gamut：规格书原色 ↔ 由矩阵反解

规格书 §2.1 / §2.2：

| | CIE x | CIE y |
|---|---|---|
| Red | 0.7063 | 0.2957 |
| Green | 0.1913 | 0.9623 |
| Blue | 0.1115 | -0.0492 |
| White (D65) | 0.3127 | 0.3290 |

**反向验证**：只用 DCTL 的 `M_AP0` 和我自己算的 AP0→XYZ，反解原色：

| 假设的 AP0 基底 | 反解原色与规格书原色表的最大偏差 |
|---|---|
| **AP0 按 D65 归一化** | **0.0001** |
| AP0 按 D60 归一化（ACES2065-1 标准） | 0.0116 |
| Bradford D60→D65 后的 D60 基底 | 0.0142 |
| Bradford D65→D60 后的 D60 基底 | 0.0348 |

只有"AP0 按 D65 归一化"能还原出规格书印的原色，其余差 1–3 个千分点。

---

## 3. 四张矩阵：全部自洽

规格书 §2.4 给出四张 3×3，用原色 + 白点独立重建后对照：

| 矩阵 | 规格书 | 重建结果 | 最大差 |
|---|---|---|---|
| `M_XYZ`（vivoWG → CIE XYZ D65） | §2.4.1 | 由原色 + D65 计算 | 2.9e-4 |
| `M_AP0`（vivoWG → ACES AP0） | §2.4.3 | inv(AP0@D65) · M_XYZ | 4e-4 |
| `M_DWG`（vivoWG → DaVinci Wide Gamut） | §2.4.2 | inv(DWG@D65) · M_XYZ | 1.0e-4 |
| `M_709`（vivoWG → ITU-R Rec.709） | §2.4.4 | inv(709@D65) · M_XYZ | 4e-4 |

最大差都在 4 位小数的舍入量级（1e-4），四张矩阵互相一致。

---

## 4. 由 §3 得出的结论：`M_AP0` 的白点

同一张 `M_AP0` 用两种 AP0 基底去重建，差 200 倍：

```
AP0@D65 :  4e-4        ← 吻合
AP0@D60 :  8.9e-2      ← 差 8%
```

也就是说，规格书（以及 DCTL）里说的 "ACES AP0"，是**把 AP0 原色按 D65 归一化**，
不是 ACES2065-1 定义的 D60 归一化。这一点用规格书自己的两张矩阵就能判定，不依赖任何外部约定。

后果：中性白经该矩阵后得到 AP0 (1, 1, 1)；若下游按标准 ACES（D60）解释，
其对应的中性应该是 (0.998, 1.009, 1.080)——蓝通道差 8%。

页面提示里写明了这一点，并按 D65 处理。
