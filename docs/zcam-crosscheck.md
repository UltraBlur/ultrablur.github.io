对象：`/colour/zcam-zlog2/`。
依据：`~/Downloads/ZLog2与Z-RGB.md`（含官方 4096 点 LUT 拟合结果、
官方 DCTL `zlog2_to_acesap0.dctl` 的矩阵推导），以及 `cinity-ofx-re` 的逆向分析。

## 1. Z-Log2 曲线

单段对数，没有线性趾部、也没有额外的黑位压缩：

```
V = c·log10(a·L + b) + d
L = (10^((V − d)/c) − b) / a

a = 4.8615   b = 0.226127   c = 0.3455   d = 0.385537
```

这里 **L 是相对 18% 的线性标度**（18% 灰 = 0.18），
因此 18% 落在码值 **0.400**，码值 1.0 对应 L ≈ 12.30，即 **+6.1 档**。

另一种写法（满量程归一，1.0 = 剪切点）用 `a = 59.7803`、`L → L/12.297`，
两者是同一条曲线：59.7803 / 12.297 = 4.8615。

### 与官方 LUT 的对照（来自参考文档 Table 2）

| Stops | −9 | −6 | −4 | −2 | 0 | +2 | +4 | +6 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| Z-Log2 | 0.164 | 0.171 | 0.195 | 0.264 | **0.400** | 0.583 | 0.784 | 0.990 |
| 页面曲线 | 0.164 | 0.171 | 0.195 | 0.264 | **0.400** | 0.583 | 0.784 | 0.990 |

逐档一致。

### 一处曾经的错误（已修）

第一版把 CINITY 插件里的**满量程**常数（`a_eff = 59.7803`）直接配上了
**18% 标度**的输入（`L = 0.18`），于是 18% 被算成 0.745。
两者相差正好 12.297 倍（S_clip），属于把两套标度混用 —— 已改用 `a = 4.8615`。

## 2. Z-RGB 色域

由官方 DCTL 的 `M`（Z-RGB → ACES AP0）剥离各通道不等比增益后反求：

| | CIE x | CIE y |
|---|---|---|
| Red | 0.6805 | 0.2474 |
| Green | 0.2806 | 1.0151 |
| Blue | 0.0813 | −0.0960 |
| White | 0.3217 | 0.3377（D60） |

绿原色 y > 1、蓝原色 y < 0，都落在 CIE 1931 可见轨迹之外 —— 宽色域的正常形态。

RGB → XYZ（页面 `matrix` 字段）：

```
[ 0.609600  0.246621  0.096426 ]
[ 0.221652  0.892240 -0.113892 ]
[ 0.064511 -0.259916  1.204230 ]
```

**核对**：用上面 4 个点按标准方法重建 RGB→XYZ，与本矩阵最大差 **1.3e-4**，
白点行和 = (0.9526, 1.0000, 1.0086)，与 D60 的 XYZ 一致。

三角形面积 0.2987（xy），约为 ARRI Wide Gamut 3（0.2560）的 1.17 倍。

## 3. 与 ARRI LogC3 / Wide Gamut 3 的差别

| | Z-Log2 | LogC3 (EI800) |
|---|---|---|
| 形式 | 单段对数 | 对数 + 线性趾部 |
| 中灰码值 | 0.400 | 0.391 |
| 码值 1.0 | +6.09 档 | +8.26 档 |
| 高光端每档码值增量 | 0.104 | 0.074 |

Z-Log2 的中灰位置与 LogC3 接近，但**高光余量少约 2 档**，所以中灰以上爬升更快。
