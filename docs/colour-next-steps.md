## 1. 色体积可视化（仿 ColorSync）

### 目标

现在只有 CIE 1931 xy 的二维三角形。目标是给出真正的三维色体积：把 RGB 立方体映射到目标色彩空间的三维坐标，画出体积与截面，可以和参考色域叠放比较。

### 支持的坐标空间

| 坐标 | 用途 | 备注 |
| --- | --- | --- |
| XYZ | 线性基础 | 与所有变换的中转站 |
| Lab (CIE 1976 L\*a\*b\*) | 感知均匀 | 常用参考 |
| Luv | 感知均匀 | 色度线性更好 |
| xyY | 传统 | 与现有二维图对应 |
| ICtCp | HDR / Rec.2100 | PQ 体系下更均匀 |
| Oklab | 现代感知 | 计算便宜 |
| CAM16-UCS | 现代 UCS | 实现较重，可选 |
| Jzazbz | HDR 感知 | 可选 |

### 数据与算法

1. RGB → XYZ：直接用页面已有的 `matrix`（RGB→XYZ），无需新数据。
2. XYZ → 目标坐标：每个坐标空间一个纯函数，放在 `assets/js/colour-spaces3d.js`。
3. 体积生成：对 RGB 立方体做 N³ 采样（N=17 约 4900 点）或沿六个面生成网格；外表面用凸包或直接画 6 个面（每面 N² 网格）。
4. 渲染：
   - 方案 A：Canvas 2D + 手写投影（零依赖，和现有代码风格一致，体积用半透明面片 + 深度排序）。
   - 方案 B：引入 three.js（约 150KB min）。**倾向 A**，理由：当前项目零依赖，且色体积不需要光照/材质。
5. 参考体积：sRGB / P3-D65 / Rec.2020 三选一叠加，线框显示。

### 交互

- 拖拽旋转、滚轮缩放、双击复位
- 切换坐标空间（下拉）
- 切换参考体积（无 / sRGB / P3 / Rec.2020）
- 显示/隐藏 Lab 的 L 轴刻度
- 移动端：单指旋转、双指缩放

### 页面结构

- 条目页顶部加「三维」页签，与现有 xy 图并列
- 独立页面 `/colour/volume/` 支持多空间叠加

### 风险

- 移动端 4900 点 + 半透明面片的帧率
- 感知空间（CAM16-UCS）实现复杂，先跳过，作为后续

## 2. 色彩空间比对

### 目标

任选两个（或三个）色彩空间，叠加色域三角形与编码曲线，给出定量差异。

### 功能

1. **色域叠加**：同一张 CIE 1931 xy 图上画多个三角形，颜色区分，图例可点选。
2. **曲线叠加**：同一坐标系里画多条编码曲线（横轴 stops 或相对亮度）。
3. **定量指标**：
   - 色域面积比（xy 面积 / 覆盖率），注明 xy 不是感知均匀
   - 体积比（在 Lab 或 Oklab 下）
   - 共有区域 / 各自独有区域
4. **入口**：`/colour/compare/?a=srgb&b=p3-d65`，URL 可分享；侧边栏加「比对」入口。

### 数据

全部来自现有 `data/curves.json` + 各页 front matter（primaries / white / matrix），不需要新数据源。

### 实现要点

- 抽出现有 `initGamut` / `initCurve` 的绘制逻辑为可复用函数，接受数组形式的 series
- 比对页复用同一套坐标轴与配色

## 3. 换算器

### 3.1 Camera Encoding：曝光档位 ↔ 码值

- 输入：stops（相对 18% 灰）或编码码值
- 输出：另一个 + 线性值 + 10-bit / 12-bit 码值
- 数据：`data/curves.json` 已经存了 −8…+12 档的采样（161 点），直接线性插值；反向用二分/线性搜索
- 边界：曲线在 1.0 以上继续上升，界面要允许超出或提示裁切
- 每条曲线注明「码值 1.0 对应多少 stops」

### 3.2 Display Encoding：亮度 ↔ 码值

分三类，是否需要「峰值亮度」输入取决于是不是绝对亮度体系：

| 类型 | 条目 | 需要输入峰值亮度？ |
| --- | --- | --- |
| 绝对亮度，EOTF 直接给出 nits | ST.2084（PQ）、CINITY Log | **不需要**，码值直接对应绝对亮度 |
| 绝对显示，但 OOTF 依赖显示峰值 | HLG | **需要**（峰值亮度 + 系统伽马 1.2 / 1.0） |
| 相对亮度（0–1） | sRGB、Rec.709、Rec.2020（BT.1886）、Adobe RGB、P3-D65、P3-DCI | 不需要，只做码值 ↔ 相对亮度 |

- PQ：码值 ↔ 绝对亮度（0–10000 nits），ST 2084 公式直接算
- CINITY Log：100 nits 白 + 0.01 nits flare，绝对亮度直接算
- HLG：码值 → 场景光 → 按峰值亮度施加 OOTF → 显示亮度；峰值不同结果不同，必须输入
- 相对体系：码值 ↔ 相对亮度（BT.1886 的 2.4 gamma），不涉及绝对 nits

界面：码值 / 相对亮度 / 绝对亮度三个输入联动；只有 HLG 多出一个「峰值亮度」输入框。相对体系的条目，绝对亮度一栏留空或标注「该空间为相对亮度，无绝对亮度」。

### 数据

需要补充每个显示条目的类型标记，例如 front matter 增加：

```toml
transferKind = "absolute"     # absolute | absolute-hlg | relative
peakLuminanceDefault = 1000   # 仅 HLG 使用
```

## 4. 实施顺序

1. **换算器**（最小、收益直接）：先做 Camera 的 stops ↔ 码值，复用现有曲线采样。
2. **比对**：先做色域叠加 + 曲线叠加，定量指标随后。
3. **三维体积**：先做 Canvas 2D 投影 + XYZ/Lab 两种坐标，跑通后再加 Oklab / ICtCp。
